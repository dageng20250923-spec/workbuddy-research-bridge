# 接入门槛与失败处理

## 首次准备检查

必须由该 PC 用户选择工作目录、自己的 Zotero 文库与 Obsidian 库；不是开发者现有个人目录。必须确认接收服务确实上线且用户已绑定自己电脑。临时测试 HTTPS、共享 Token、单发送方白名单不等于多租户服务。

确认安装/启用 scansci-pdf 技能，且 WorkBuddy 桌面能够调用其合法来源工具/适配器。不得仅根据技能出现、套件有 download 方法或设置 use_tor=false 判为安全接入。无法核验实际生效的来源白名单时，报告 needs_configuration，不执行下载。

迁移包没有捆绑第三方下载套件、Python、Zotero XPI 或 Research Bridge。发布者仍须核验版本、分发许可和路径参数化。不要让模型自动执行未知安装脚本，不读取或显示其他应用密钥。正式发行时这些依赖应通过可核验的安装器/下载地址及兼容检查解决。

WorkBuddy 桌面本地模式才能访问本机 Zotero/Obsidian。云端任务不能直接访问用户的 localhost。当前准备包未经过 WorkBuddy 导入及定时任务实测，不承诺某个未核验的配置文件格式或自动化 API。

## 现有开发工程的限制

现有 batch/library_handoff.py 与 observe_handoff.py 仍有开发者路径，不可在他人电脑直接运行。paper_batch.py 的旧自动下载分支不满足所有未来下载通过 scansci-pdf 的新约定，不能把它直接设成 WorkBuddy 自动下载命令。

scansci_adapter.py 已通过隔离方式调用旧套件的 NatureDirect，保留旧安装；尚未支持全出版社，尚未构成跨用户完整下载接口。读取原 skill 后通过这一适配层调用才是受控技能编排，不可编造一次 scansci MCP 调用记录。

report_jobs.py 只用标准库，唯一参数是用户明确授权的 batch 目录。它选取数字文件名账本、验证已记录文件的范围/哈希，读取对应本机观测报告的少量状态。它不宣称独立重做论文身份/全文许可核验。未知错误只输出固定原因，不显示可能带 Cookie/API key 的原始异常。

## 失败行为

| 情形 | 状态/处理 |
| --- | --- |
| 缺技能、工具、来源策略或真实服务 | 需配置，停止下载 |
| 公众号验证码/主论文不明/多篇歧义 | 待确认 DOI，不批量猜测 |
| 无合法全文访问、出版社限制 | 未下载，列 DOI、题名和访问建议；不弹登录框 |
| HTTP 200 HTML、预览、身份/版本不匹配 | 校验失败；不得导入 |
| PDF 已下载但 Zotero 关闭/接口失败 | 待导入，不误报“下载失败” |
| 导入请求失联 | 对账中；不得重复 POST |
| PDF/条目已成功、文献卡未出现 | 笔记待同步；不重复导入 |
| AI 暂停或预算未知 | 已入库但 AI 未完成；提示主动检查，不自动付费重试 |
| 队列/报告缺失或损坏 | 需检查配置/账本；不能报告空队列正常 |

## 通知示例

“本批已下载 3 篇，未下载 2 篇。未下载：任务 4，题名/DOI，出版社要求合法访问；任务 5，题名/DOI，PDF 身份不符。请选择提供合法访问或暂缓。另有 1 篇已入 Zotero、AI 暂停，不需重复下载。”

仅有旧账本而未连接正式接收服务时，要说明“这是本机记录，不是新收到消息的实时统计”。通知去重 fingerprint 不代表已送达。下载失败项保持在待处理清单，直到成功、用户明确暂缓或取消；不能因为已经提醒就删除任务。
