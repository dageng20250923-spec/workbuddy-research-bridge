# 微信公众号接入说明 · PaperFlow 文献整理中心

日期：2026-10-09。本文描述把现有接收服务端（`receiver/receiver.py`）接入微信公众号后台所需的配置，以及后续接 scansci-pdf / Zotero 的路线。当前是**本地验证版**，不是公众正式服务。

## 一、现状：服务端已具备的能力

`receiver/receiver.py` 是一个生产级的微信官方回调接收器（标准库实现，只监听 127.0.0.1），已经实现：

- 官方明文回调的 GET URL 校验、POST 验签（SHA1，时间窗口 ±600 秒、重复参数检查）。
- 只接受配置的目标公众号 + 发送方 OpenID 白名单；白名单未填或账号不明时拒绝启动。
- 纯文字中的 DOI / doi.org 地址 / 公众号文章链接提取；不处理文章卡片、附件、群消息、历史聊天。
- 事务性 SQLite 持久化、MsgId 去重、候选去重；写失败返回 503 不假称成功。
- **被动文本自动回复**（本次新增）：成功入队 / 重复 / 非文本 / 无候选时，返回固定 text/xml 确认文案，不回显 DOI、正文或身份。
- 一次性配对绑定（pair-init / serve-pairing / pair-confirm），唯一发送者白名单。

## 二、微信公众号后台配置

在公众号后台「设置与开发 → 基本配置 → 服务器配置」填写：

| 项 | 值 | 说明 |
| --- | --- | --- |
| URL | `https://<你的域名>/wechat/callback` | 必须是公网 HTTPS，微信会向此地址发起 GET/POST |
| Token | 与 `runtime/local-config.json` 的 `callback_token` 一致 | 仅本地保存，不贴到聊天 |
| EncodingAESKey | 明文模式下留空即可 | 当前未实现加密模式，收到 Encrypt 会明确拒绝 |
| 消息加解密方式 | 明文模式 | 加密模式尚未实现 |

微信会先做一次 GET 校验（带 echostr），服务端回显 echostr 即通过。校验通过后，用户在公众号对话里发文字 DOI 或文章链接，会触发 POST 回调。

### 关键前提（当前尚未满足）

1. **正式服务号**：普通订阅号/未认证号不具备消息回调权限，需已认证的服务号。
2. **公网 HTTPS 域名**：当前服务只监听 127.0.0.1，需经可信任的 HTTPS 反向代理/隧道（如 Cloudflare Tunnel）或正式托管服务器对外暴露，且绑定固定域名。
3. **多租户安全**：当前是单用户原型（白名单 1 人），正式版需账号隔离、租户队列、数据保留、限流与解绑，见 `docs/plans/2026-10-09-shared-workflow.md`。

## 三、被动回复与菜单/自动回复

- **被动回复**：服务端已实现，用户发 DOI 后立即收到"已收到，正在排队整理"的固定确认。这是消息管理接口的"回复"半边。
- **菜单**：在公众号后台「自定义菜单」配置，建议三个入口：① 发送文献（提示粘贴 DOI/链接）；② 绑定电脑（引导设备配对）；③ 查看进度（未来接任务中心）。
- **自动回复**：后台「自动回复」可配置被关注回复、关键词回复；但文献消息的确认由服务端被动回复负责，不要在后台关键词回复里重复承接 DOI。

## 四、绑定流程（设备配对）

1. 服务端运行 `pair-init`，生成 15 分钟有效的高熵配对码（只写 `runtime/pairing-code.txt`）。
2. 切换到 `serve-pairing`，用户向公众号发送配对码文字。
3. 服务端记录候选（只存验证码哈希 + 一组身份），**不自动授权**。
4. 用户在 PC 上确认后运行 `pair-confirm`，写入唯一发送者白名单。
5. 切回 `serve`，开始接收该发送者的文献消息。

配对只授权一个发送者；过期码不接受；解绑需单独实现。

## 五、后续接真实整理（路线，未实现）

接收服务端只负责"收消息 + 入队 + 回复确认"，真实整理仍按 HANDOFF 既定顺序：

1. 客户端（PC 上的 WorkBuddy 桌面本地任务）从队列领取有界批次。
2. 逐篇调用 `scansci-pdf` 技能（已安装、已核验合法来源白名单），校验 PDF 内容/题名/DOI/版本/哈希。
3. 经授权调用本机 Zotero 接口导入，DOI 去重，只命名附件副本，成像方法分类。
4. 本机 Obsidian Research Bridge 生成/同步文献卡，可选用户授权的 AI。
5. 失败逐篇列清单，通过正式服务的通知回执推送；相同 fingerprint 不重复提醒。

当前这些环节仍是**待接入**状态：本地客户端 0.2 是 simulation 演练（不下载、不写文库），不能当作真实整理已上线。

## 六、绝不动

- 不读个人微信数据库、不监听/检索微信界面、不弹窗、不抢焦点。
- 不把 DOI 格式通过当身份或下载成功；不批量抓公众号参考文献。
- 不自动用预印本替正式版；禁止 Tor / Sci-Hub / LibGen / 自动机构登录。
- 服务端不收全文、个人笔记、AI 密钥、机构 Cookie；下载和文库处理留在用户自己的 PC。
